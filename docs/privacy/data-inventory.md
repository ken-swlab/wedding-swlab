# データの一覧（Issue #105）

最終更新: 2026-10-12（コード・Rules・Terraform から作成。「オーナー確認」と書いた箇所は、Claude からは見えない設定）

何を・どこに・誰が見られる形で・いつまで持っているか。削除の手順は [deletion-runbook.md](deletion-runbook.md)、外部のサービスは [subprocessors.md](subprocessors.md)、ゲストに見せる文面の案は [privacy-policy-draft.md](privacy-policy-draft.md)。

- **このファイルに、個人情報の値は書かない。**書くのは、項目の名前と置き場所だけ。
- このリポジトリは公開されている。プロジェクト ID・連絡先も書かない。
- 法的な判断（どの情報が何に当たるか、何を告知すべきか）は、していない。専門家に確かめる。

## 1. まとめ

- **保持期間は、決まっていない。**ゲストのデータ（プロフィール・回答・投稿・写真・顔の記録）には、自動で消える仕組みが無く、消すまで残る。期限があるのは、ログとバックアップだけ（§4）。イベントのあといつまで持つかは、オーナーが決める（[deletion-runbook.md](deletion-runbook.md) §4）。
- **とくに扱いに気をつける情報**: アレルギー・備考（健康の情報が入りうる）、顔の記録（顔の位置と、照合用の特徴データ）、原本の写真（EXIF に位置情報が入りうる）、本名とふりがな。
- **消しても残るもの**がある（§5）: R2 の原本（非公開）、配信のキャッシュ、バックアップ（最長 14 週）、監査ログ（400 日。消せない）。公開側の写真は、投稿を消すと消える（Issue #122）。

## 2. ゲストのデータ（Firestore。リージョンは asia-northeast1）

「管理者」は新郎新婦（Custom Claims の `admin`）。「承認済みゲスト」はタグを 1 つ以上持つ人。「サーバー」は Admin SDK（Rules を通らない）。

**uid の形:** LINE でログインした人は `line:<LINE のユーザー ID>`。名簿だけの仮登録は `pre_…`（本人がログインすると、`mergedInto` で本物の uid に付け替わり、仮の文書は `isArchived` で残る）。**uid そのものが LINE のユーザー ID を含む**ので、uid が残る場所（監査ログ・ほかの人の投稿の `mentionUids` など）には、仮名の識別子が残ることになる。

## 4. ログとバックアップ

| 監査ログの写し | GCS（ロック済み） | 上と同じものの、毎日の写し | オーナー（GCP） | **400 日。ロック済みで、期限まで誰にも消せない** | 消せない |
| 個人情報の閲覧ログ | Cloud Logging（`pii-access`） | `guestPrivate`・`guestAdmin`・`faces`・`auditLogs` を「誰が・いつ・どこから（IP）読んだか」。読んだ人の uid と、トークンの中身（**LINE の表示名**を含む）が入る。読んだ値は入らない | オーナー（GCP） | **400 日**（ロックはしていない） | オーナー（GCP）。ロックするまでは消せる |
| GCP の既定のログ | Cloud Logging（`_Default`） | 上の閲覧ログも、いまはここにも入る（第 2 段階に進むと外れる。`data_access.tf`） | オーナー（GCP） | 30 日 | 自動 |
| レート制限の記録 | Firestore `rateLimits` | ルート名・窓・回数。uid や IP は、ハッシュにして ID の一部にするだけ | なし | 窓が閉じてから数分（TTL。実際に消えるまで最大 1 日ほど遅れる） | 自動 |
| Firestore のバックアップ | GCP（PITR・定期バックアップ） | **Firestore の全部**（§2 のすべて。本名・アレルギー・顔の記録を含む） | オーナー（GCP） | PITR 7 日、日次 7 日、**週次 14 週** | 期限で自動。個別の文書だけを消すことはできない |
| エラーの報告 | Sentry | エラーの内容、ルート名、リクエスト ID。**本文・ヘッダ・Cookie・IP・uid は送らない**（`sentry-scrub.ts`）。CSP の違反レポートも届く | オーナー（Sentry） | Sentry のプランによる（**オーナー確認**） | Sentry の管理画面 |

| Worker のログ | Cloudflare | 処理した原本のキー（uid が入る）と結果 | オーナー（Cloudflare） | 設定による（オーナー確認） | 自動 |
| 運用の一時ファイル | 開発機（`pii-backup-*.json`） | 過去の移行（`migrate-pii.mjs`）が作る、個人情報の控え。Git には入れない | オーナー | 消すまで | 手で消す。**残っていないか、オーナー確認** |

## 5. 「消しても残る」もの（現状の仕様）

| 何を消したとき | 消えるもの | 残るもの |
|---|---|---|
| ゲストが自分の投稿を消す（`/api/posts/[id]` DELETE） | 投稿・そのコメント・いいね・顔の記録（`faces`）、**公開バケットの軽量版と高画質版**、その写真の Rekognition の顔の特徴（Issue #122） | **非公開バケットの原本とマーカー**（Issue #159）。配信のキャッシュ（下の注意）。ほかの人あての通知。バックアップ（最長 14 週）。監査ログ（`post.delete` の記録。消した数だけ。400 日） |
| ゲストが投稿の写真を外す（PATCH） | 外した写真の顔の記録、公開バケットの軽量版と高画質版、Rekognition の顔の特徴 | 外した写真の原本とマーカー。配信のキャッシュ |
| ゲストがアイコンを変える | — | 前のアイコン画像（R2） |
| 管理者がゲストを停止する（アクセス停止） | タグ（見える範囲）とログイン中のセッション | すべてのデータ（停止は削除ではない） |

- **原本を消さないのは、意図した作り**（原本は作り直せない。誤って消す操作がどのくらい起きるかを見てから決める。CLAUDE.md ルール 18・Issue #159）。原本まで消す依頼には、オーナーが手で R2 を消す（[deletion-runbook.md](deletion-runbook.md) §2）。
- 公開側の写真の削除は、R2 の失敗で投稿の削除を止めない。消せなかったときは、Sentry に投稿 ID と位置（何枚めの軽量版・高画質版か）が残る。キーそのものはログに出さない（uid が入る）。
- 同じキーを本人のほかの投稿（新しい順に 300 件）やアイコンが使っていれば、消さない（API を直接呼んだときだけ起きる）。
- **配信のキャッシュ（見立て。オーナー確認）:** R2 から消しても、Cloudflare のキャッシュと、すでに見た人のブラウザのキャッシュは消えない。
  - 軽量版（`t/`）: アップロードのときに `Cache-Control` を付けていない。Cloudflare の既定では、エッジに最長およそ 2 時間、ブラウザに最長およそ 4 時間残る見込み（ゾーンのキャッシュ設定による）。
  - 高画質版（`o/`）: Worker が `Cache-Control: public, max-age=31536000, immutable` を付けている。**エッジに残っている間は開ける**（アクセスが無ければ早めに追い出されるが、時期は決まっていない）。ブラウザには最長 1 年残る。
  - 確実に消すには、Cloudflare の管理画面（Caching → Configuration → Custom Purge）で URL を指定して消す（[deletion-runbook.md](deletion-runbook.md) §2 の注意）。自動で消すには、キャッシュの削除の権限を持つ API トークンが要る（未実装。要るかどうかはオーナーが決める）。

## 6. 外部に渡るデータ

どのサービスに何が渡るかは [subprocessors.md](subprocessors.md)。要点だけ:

- 顔検出のとき、**写真（軽量版）のバイト列**が AWS Rekognition に送られる（保存されるのは、管理者が確定した顔の特徴だけ）。
- 管理者が AI の試験（`/admin/ai-test`）をすると、**相手のゲストの呼び名・本名・タグ・運営のメモ・エピソードの本文**が Vertex AI に送られる。ゲストが使う AI の機能は、まだ無い。
- 音声合成（管理者だけ）は、読み上げる文だけを Modal に送る。
- 公式 LINE の通知（Issue #168）は、**通知の文面と、宛先の LINE のユーザー ID**を LINE（Messaging API）に送る。文面は決まった文（例:「承認されました」）とゲストブックの URL だけで、本名・アレルギーなどは入れない。送るかどうかは `config/runtime` の `lineNotify`（既定 off）。
- Sentry には、個人を特定できる値を送らない作りにしている。

## 7. まだ確かめていないこと（オーナー確認）

- Sentry・Vercel・Cloudflare のログの保持期間（プランと設定による）
- R2 のバケットの場所（ロケーション）と、ライフサイクルの設定
