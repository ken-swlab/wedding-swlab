# 脆弱性の報告について（Vulnerability Disclosure Policy）

最終更新: 2026-10-12

招待制のウェディングサイト（`https://wedding.sw-lab.net`）と、このリポジトリのコードについて、脆弱性を見つけた方からの報告を受け付けます。個人が運営する小さなサービスで、報奨金はありません。

機械向けの案内は [`/.well-known/security.txt`](https://wedding.sw-lab.net/.well-known/security.txt)。

## 連絡先

- メール: **security@sw-lab.net**（日本語・英語）
- 公開の Issue には、脆弱性の詳細を書かないでください（先にメールでお知らせください）。

## 報告に書いてほしいこと

- 何が起きるか（影響）と、対象の URL・画面・API
- 再現の手順（できるだけ短く）
- 確認した日時と、使った環境（ブラウザなど）

実在のゲストの個人情報が見えてしまった場合は、**その内容を報告に貼らず**、「見えた」という事実と項目名だけを書いてください。手元に保存したものは消してください。

## こちらの対応

| | 目安 |
|---|---|
| 受け取った旨の返信 | 3 営業日以内 |
| 影響の評価と、対応の方針の連絡 | 10 営業日以内 |
| 修正 | 影響の大きさによる。個人情報に関わるものを最優先 |

- 修正が済むまで、詳細の公開を待ってください（目安は 90 日。長引くときは相談します）。
- 善意で、下の「しないでほしいこと」を守って行われた調査について、法的な措置を求めません。
- 希望があれば、修正後に、報告者のお名前を謝辞として載せます。

## 対象

- `https://wedding.sw-lab.net`（ページと `/api/`）
- 写真の配信（`https://wedding-media.sw-lab.net`）
- このリポジトリのコード（アプリ、Firestore の Rules、Worker、Terraform）

とくに知りたいもの: 認証・権限の回避（招待されていない人が読める、ほかの人の情報を読める・書ける、管理者の操作ができる）、個人情報や位置情報の漏えい、XSS、秘密情報の混入。

## しないでほしいこと

- **ほかの人のデータの閲覧・変更・削除。**確かめるのは、自分のアカウントと自分のデータで。権限を越えられると分かった時点で止めて、報告してください。
- サービスを止める・重くする行為（DoS、大量のリクエスト、総当たり）。自動スキャンは、ごく低い頻度で。
- ゲストや運営者への、フィッシングなどの社会工学。物理的な侵入。
- 第三者のサービス（Vercel・Google・Cloudflare・LINE・Sentry・AWS・Modal）そのものへの攻撃。それらの脆弱性は、各社の窓口へ。

## 対象外

- 悪用の道筋を伴わない指摘（HTTP ヘッダの有無だけ、バージョンの表示だけ、など）
- 古いブラウザでだけ起きる問題
- レート制限で止まる範囲の総当たりが「できる」こと
- 招待された本人が、自分に見せてよい情報を見られること
- スパム、メールの送信ドメインの設定（SPF・DKIM・DMARC）の指摘だけのもの

## 受け取ったあとの流れ（運営者向け）

[../ops/incident-response.md](../ops/incident-response.md) の重大度 S4 として扱う。悪用の形跡があれば、S1〜S3 に上げる。受け取りと対応の記録は、公開されない場所に残す。`security.txt` の `Expires` は期限つきなので、切れる前に更新する（2027-09-30）。
