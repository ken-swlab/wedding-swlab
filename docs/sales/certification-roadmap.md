# 第三者診断と認証の方針メモ（Issue #106）

最終更新: 2026-10-13（料金と条件は、同日に各公式ページで確かめた。**変わるので、申し込む前に見直す**）

法人から「診断は受けているか」「ISMS・プライバシーマークはあるか」と聞かれたときの、現状と、決めるための材料。**決めるのはオーナー。**ここには選択肢と提案だけを書く。

## 1. いまの状態（事実）

| 項目 | 状態 |
|---|---|
| 第三者による脆弱性診断・ペネトレーションテスト | **受けていない** |
| ISMS（ISO/IEC 27001） | **取得していない** |
| プライバシーマーク | **取得していない**（いまの体制では申請できない。§3） |
| SOC 2 などの監査報告書 | **無い** |
| 自分で行っている検査 | CI の自動の検査（秘密の混入・依存の脆弱性・静的な検査・Rules のテスト）と、定期の棚卸し。第三者の目は入っていない |

**書き方の決まり:** 「取得予定」「準拠」「相当」「診断済み」と書かない。利用している各社（Google・Cloudflare・AWS・Vercel）の認証は、その会社のもので、このサービスのものではない。

## 2. 第三者診断

### 前提: いまのホスティングでは受けられない

Vercel の案内では、利用者が自分のデプロイに対して診断を行えるのは **Pro と Enterprise** で、**Hobby では認められていない**（[Penetration testing on Vercel](https://vercel.com/kb/guide/penetration-testing-on-vercel)）。同じページの条件:

- 大量のリクエストを送らない診断は、Pro・Enterprise なら事前の連絡は要らない。大量のリクエストを伴う診断は Enterprise だけで、事前の連絡が要る。
- 対象は自分のアプリだけ。Vercel の基盤そのものを狙わない。
- 診断が影響する、ほかのサービス（データベースなど）の同意を取る。→ **Firebase / Google Cloud・Cloudflare・AWS のそれぞれの診断の規約を、診断の前に確かめる**（今回は調べていない）。
- 診断で増えた通信や関数の実行の料金は、利用者の負担。

→ 診断を頼むなら、先に Pro 以上へ変える（[commercial-readiness.md](commercial-readiness.md) §1）。

### 何を診てもらうか（範囲の候補）

| 対象 | 中身 | 優先度（提案） |
|---|---|---|
| Web アプリと API | 認証・権限の回避（招待されていない人が読める、ほかの人の情報を読める・書ける、管理者の操作ができる）、入力の検証、セッション | 高 |
| データベースの Rules | ブラウザから Firestore を直接読む・書く経路で、見える範囲を越えられないか | 高（この構成に特有。診断会社が Firestore の Rules を診られるかを、先に確かめる） |
| 写真の配信（R2） | 公開側の URL の推測、原本への到達、アップロードの署名の悪用 | 中 |
| クラウドの設定 | GCP の IAM・ログ・バックアップ、Cloudflare、Vercel の設定の点検 | 中（設定の診断は、別の商品のことが多い） |
| 負荷・DoS | — | 対象にしない（Vercel の規約で、Pro では不可） |

### どこに対して行うか

**本番（実在のゲストのデータがある）ではなく、作りもののデータを入れた検証環境に対して行うのが望ましい。**診断では、権限を越えて他人のデータが見えることを確かめる。本番で行うと、診断会社が実在のゲストの本名・アレルギーを見ることになる。いまは、本番と同じ構成の検証環境が無い（[commercial-readiness.md](commercial-readiness.md) §1 の「検証用の環境」）。

### いつ行うか（選択肢）

| 案 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| A. 機能の追加が落ち着いたあと | セキュリティの基礎の Issue と、公開側の写真まわりの修正（Issue #29・#122・#123）を終え、機能を凍結してから | 分かっている穴を先にふさげるので、診断の費用が、知らない問題を見つけることに使われる | 凍結の時期を決めないと、いつまでも始まらない |
| B. 法人への提供の直前 | 契約の前、または契約の条件として | 提供する版をそのまま診てもらえる。相手の指定する形式（報告書の様式・診断会社）に合わせられる | 指摘の修正の時間が要る。日程が相手に左右される |
| C. 行わない | 自動の検査と自己点検だけで答える | 費用がかからない | 「未実施」と答え続けることになる。法人の基準によっては、導入の条件を満たさない |

**提案: A を基本に、B の要望が先に来たら B。**順番は、①既知の穴の修正 → ②Pro への変更と検証環境 → ③見積もり（2〜3 社）→ ④診断 → ⑤指摘の修正と再診断。

- Issue #106 の「A〜D 完了後」の A〜D が何を指すかは、**オーナー確認**（Issue の本文とリポジトリからは特定できなかった。セキュリティの基礎の Issue #102〜#105 のことだと読んで、上の案 A を書いた）。
- **費用は、調べていない**（範囲と日数で大きく変わる。見積もりで確かめる）。見積もりを頼むときに伝えること: 画面と API の数（API は 25 ルート）、権限の種類（未ログイン・未承認・ゲスト・管理者）、Firestore の Rules を診る必要があること、検証環境の有無、報告書の言語と様式、再診断の有無。
- 診断会社を選ぶ手がかりとして、経済産業省の基準に基づく「情報セキュリティサービス基準適合サービスリスト」（IPA が公開）がある（今回は中身を確かめていない）。

## 3. 認証

### 比べる

| | プライバシーマーク | ISMS（ISO/IEC 27001） |
|---|---|---|
| 何を見るか | 個人情報の取り扱いの仕組み（JIS Q 15001） | 情報セキュリティ全般の管理の仕組み |
| 単位 | **法人ごと**（会社全体） | 範囲を決められる（事業・部署・拠点） |
| 申請できる条件 | 国内に拠点のある事業者。**社会保険・労働保険に加入した正社員、または登記上の役員（監査役を除く）が 2 名以上**。個人情報保護管理者と監査責任者は**別の人**で、どちらも従業者（[JIPDEC: 申請資格](https://privacymark.jp/p-application/qualification.html)） | 認証機関による（**1 名の体制で受けられるかは、調べきれていない**。認証機関に確かめる） |
| 有効期間 | 2 年（更新の審査） | 3 年（毎年の維持審査と、3 年ごとの更新審査） |
| 公式の料金 | 下の表（JIPDEC） | 認証機関ごとの見積もり（公定の料金表は無い） |
| 通じる相手 | 日本の法人。個人情報を預ける取引で聞かれやすい | 日本と海外。IT のサービスで聞かれやすい |

**プライバシーマークの料金**（[JIPDEC: 費用](https://privacymark.jp/p-application/cost/index.html)。2026-10-01 から適用。税込・円）

| | 小規模 | 中規模 | 大規模 |
|---|---|---|---|
| 新規（申請料 + 審査料 + 付与登録料） | 336,600 | 690,800 | 1,382,700 |
| 更新（同上） | 244,200 | 518,100 | 1,037,300 |

- 区分は業種と人数で決まる。サービス業は、従業者 2〜5 人が小規模、6〜100 人が中規模。製造業・その他は、2〜20 人が小規模（[JIPDEC: 事業者規模の区分](https://privacymark.jp/p-application/cost/segment.html)）。どの業種に当たるかは、JIPDEC に確かめる。
- これは審査の料金だけ。規程づくり・教育・内部監査の手間と、外部に頼むときのコンサルの費用は、別にかかる（調べていない）。

**ISMS の費用と期間（参考。未検証）:** 公式の料金表は無い。コンサル会社の記事では、10 名以下の規模で、初回の審査が 50 万円台、毎年の維持審査が 20〜50 万円ほど、コンサルを含む取得の全体が 100〜180 万円ほど、期間は 4〜10 か月、という数字が並ぶ。**売る側の記事なので、目安にとどめ、認証機関 2〜3 社の見積もりで確かめる。**

### いまの体制に当てはめると

- **プライバシーマークは、いまは申請できない。**運営者は個人 1 名で、「法人単位」「従業者 2 名以上」「管理者と監査責任者は別の人」のどれも満たさない。取るなら、法人にして、役員か正社員を 2 名以上にすることが先。
- **ISMS も、1 名では仕組みが成り立ちにくい。**内部監査は、自分の仕事を自分で監査しない独立性が求められる（外部に頼む方法はある）。受けられるかどうかから、認証機関に確かめる。
- どちらも、取ったあとの運用（記録・教育・監査・更新）が毎年続く。披露宴 1 件のためには、釣り合わない。**法人への提供を事業として続けると決めたときの話。**

### 選択肢

| 案 | 内容 | 向いている場合 |
|---|---|---|
| A. 取らない（いまの形） | 「未取得」と答え、[security-answers.md](security-answers.md) と診断の報告書で説明する | 提供先が 1〜2 社で、相手が回答集と診断の結果で足りると言う場合 |
| B. 診断だけを受ける | §2。認証の代わりではないが、第三者の目が入った事実を示せる | 認証は要らないが、「第三者の確認」を求められる場合 |
| C. 自己宣言の制度を使う | IPA の「SECURITY ACTION」（中小企業・個人事業主向けの自己宣言。**認証ではない**。今回は条件を確かめていない） | 取り組みの姿勢を示したい場合。認証と誤解されない書き方が要る |
| D. 法人にして、認証を取る | 法人化・2 名以上の体制 → プライバシーマークか ISMS | 複数の会社に、継続して提供する場合。相手の取引の基準が、認証を条件にしている場合 |

**提案: いまは A。BP 会社へのヒアリング（[commercial-readiness.md](commercial-readiness.md) §3）で「認証が導入の条件か」を先に聞き、条件でなければ B まで。**D は、提供先が増える見込みが立ってから決める。聞かれたときの答えは「未取得です。取得の要否は、ご要件を伺って判断します」。

## 4. 運用者が 1 人であることを補う案

職務の分離（作る人と確かめる人、申請する人と承認する人を分ける）は、1 名ではできない。**できないことは「未実施」と答えたうえで**、代わりに何で補っているか・補えるかを示す。

**いま、あるもの**

| 補うもの | 中身 |
|---|---|
| 変更の記録 | すべての変更が PR とコミットに残る。`main` は保護（PR が必須、force push と削除を禁止） |
| 自動の検査 | 変更のたびに、秘密の混入・依存の脆弱性・静的な検査・Rules のテスト |
| 消せない記録 | 監査ログの写しは、ロック済みの保管場所に 400 日。運営者にも消せない |
| 取り消せない操作の歯止め | データベースの削除保護、Terraform の `prevent_destroy`、原本と監査ログを消す経路を持たない作り |
| 重要な作業の記録 | 鍵の入れ替え・棚卸し・復旧テスト・設定の変更を、日付つきで文書に残す決まり |
| 外からの報告の窓口 | 脆弱性の報告の方針と連絡先を公開 |

**足せるもの（案。未決定）**

| 案 | 中身 | 手間・費用 |
|---|---|---|
| 1. 外部のレビュー | 権限・認証・Rules・秘密に関わる PR だけ、外部の技術者に見てもらう。GitHub のブランチ保護で「承認 1 件が必須」にできる（レビュアーがいることが前提） | 人を探す必要。継続の費用 |
| 2. 第三者の定期の確認 | 年に一度、外部の人に、棚卸しの記録・アラートの履歴・監査ログの抜き取りを見てもらう（診断とは別。運用の点検） | 年に 1 回 |
| 3. アラートを本人以外にも届ける | 鍵の作成・IAM の変更の通知を、運営者のほかに、信頼できる 1 名（または提供先の窓口）にも送る。本人の不正や、アカウントの乗っ取りに気づける | 小さい。通知先を足すだけ（アラートの適用が先。[alerting.md](../ops/alerting.md) §4） |
| 4. 閲覧ログの保管場所もロックする | 個人情報の閲覧の記録を、運営者にも消せないようにする（段階の手順がある。取り消せない） | 小さいが、取り消せない。[backup-restore.md](../ops/backup-restore.md) §5 |
| 5. 緊急時の引き継ぎ | 運営者が動けないときに、止める・連絡する人を 1 名決め、手順と、封をした回復の手段を預ける | 人を決める必要。預け方の設計が要る |
| 6. 提供先に、記録を見せる | 管理画面で、その会社の式の監査ログを見られるようにする | 実装が要る（Issue #107） |
| 7. 法人化・2 名体制 | 根本の解決。認証の条件でもある（§3） | 大きい |

**提案:** 3 と 4 は小さく始められる（4 は取り消せないので、段階の手順どおりに）。法人に提供すると決まったら、1 か 2 のどちらかと、5 を足す。
