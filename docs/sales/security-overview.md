# セキュリティの概要（法人向け。Issue #106）

最終更新: 2026-10-13

招待制のウェディング SNS 兼ゲスト管理システムの、セキュリティの取り組みを 1〜2 ページにまとめたもの。項目ごとの回答は [security-answers.md](security-answers.md)。

> **お読みいただく前に**
> - 個人 1 名が開発・運用しています。**ISMS・プライバシーマークなどの認証は取得しておらず、第三者による脆弱性診断も受けていません。**
> - 現在は 1 つの披露宴のための構成で、法人への提供の実績はありません。商用の提供には、ホスティングのプランの変更などの準備が残っています（末尾の「これから」）。
> - 以下は、2026-10-13 時点の実装の事実です。

## 1. 何を預かるか

招待されたゲストの、**お名前・出欠・アレルギー、投稿された写真とコメント、LINE のユーザー ID・表示名・アイコン**です。写真からは、顔の位置と、照合用の特徴データを作ります。写真の原本には、撮影場所の情報が入っていることがあります。

LINE から受け取るのは、ログインの確認に要る 3 つ（ユーザー ID・表示名・アイコン）だけです。友だち・トーク・メールアドレス・電話番号は取得しません。パスワードは預かりません。

## 2. 構成

```
ゲストのスマホ（LINE アプリ内ブラウザ / Safari）
   │  LINE ログイン
   ▼
Vercel（アプリと API）  ── 手前に Firewall（流量の制限・ボットの遮断）
   │   すべての API に共通の関所: 認証 → 権限 → レート制限 → 監査ログ
   ├─ Google Cloud / Firebase（東京）  データベース・ログインのアカウント・監査ログ・バックアップ
   ├─ Cloudflare R2                    写真（公開用と、非公開の原本を別の場所に）
   │     └ Worker が原本の位置情報などを落としてから、公開用に複製
   ├─ AWS Rekognition                  写真の顔の検出（管理者向けの機能）
   └─ Sentry                           エラーの報告（個人を特定できる値は、送る前に除く）
```

利用するサービスと、それぞれに渡る情報の一覧は [subprocessors.md](../privacy/subprocessors.md)。

## 3. 主な対策

| 分野 | 行っていること |
|---|---|
| 見える範囲の制御 | 招待制。ゲストに付けた所属（タグ）と、投稿の公開範囲が重なる人だけが読めます。データベース側のルールで強制し、約 300 ケースの自動テストで、変更のたびに確かめます |
| 個人情報の分離 | お名前・出欠・アレルギーは、ご本人と管理者だけが読める場所に分けています。ほかのゲストに見えるのは、ニックネームとアイコンだけです（参加される方は、同じグループのゲストに「参加予定」として表示されます。回答フォームでお知らせしています） |
| 認証 | LINE ログイン。権限を変えたときは、ログインを失効させます。運用に使う 8 つのアカウントは、すべて多要素認証です |
| 不正な操作への備え | すべての API にレート制限。招待の合言葉は、失敗が続くとロックします |
| 記録 | 更新の操作を「誰が・いつ・何を」で記録します（値そのものは残しません）。写しを毎日、**運営者にも消せない保管場所**に 400 日置きます |
| 写真の位置情報 | 原本は非公開の場所に置き、位置情報などを落とした複製だけを公開します |
| ブラウザの保護 | コンテンツセキュリティポリシー（CSP）を強制し、クリックジャッキング対策などのヘッダを付けています |
| 秘密情報 | 鍵とトークンは、本番の環境にだけ置きます。一覧・入れ替えの手順書・周期を定め、コードへの混入を自動で検査します |
| 脆弱性の管理 | 依存の脆弱性・コードの静的な検査・秘密の混入を、変更のたびと毎週、自動で検査します。外部からの報告の窓口を公開しています |
| バックアップ | データベースは、過去 7 日の任意の時点と、日次（7 日）・週次（14 週）のバックアップ。復旧のテストを 1 回行いました |
| 事故への備え | 重大度・封じ込め・証拠の保全・連絡の手順書と、第一報のひな形があります |

## 4. できていないこと

隠さずに書きます。項目ごとの状況は [security-answers.md](security-answers.md)。

| 分野 | 現状 |
|---|---|
| 認証・診断 | 第三者認証は未取得。第三者による脆弱性診断は未実施 |
| 体制 | 運営者 1 名。職務の分離、24 時間の対応、人によるコードレビューはありません |
| 契約・SLA | 利用規約・稼働率の目標・サポートの時間・補償は、定めていません |
| 複数の会社・式での利用 | データを分ける仕組み（テナントの分離）、管理者の役割分け、SSO、管理画面でのログの閲覧は、ありません |
| データの保存期間 | 決まっていません。プライバシーポリシーは案の段階です |
| 削除 | 投稿を消すと、公開側の写真のファイルも消えます。非公開の原本と、アカウントごとの削除は、手順書に沿った手作業です |
| 写真 | 公開側の写真は、URL を知っていればログインなしで開けます。動画は、位置情報がついたまま公開されます（どちらも改善の予定あり）。写真のバックアップはありません |
| 監視 | エラーは集めていますが、通知のルールと、外部からの死活監視は、設定の途中です |
| データの所在 | データベースは東京ですが、配信・エラーの報告などで、日本の外のサービスを使っています |
