# プロダクトの決めごと（UTAGE / wedding-swlab）

Issue を書くとき・実装するときに、まずこれを読む。決まったことが増えたら、この文書を更新する（Issue の最後に「product-decisions.md の更新」を含める）。
本名・会場の詳細・写真・支払い情報・パスコード・鍵はここにも書かない（本番の値は `ops.mjs` で Firestore に入れる）。

## 目的とコンセプト
- 結婚式（2027 年 5 月）のための、ゲスト専用のプライベートSNS＋ゲスト管理。
- 主役は「みんなで思い出を共有し、盛り上がり、感謝を伝える場所」。結婚式らしさより同窓会らしさ。
- ゲストはほぼ水泳仲間。奥さま側の友人・会社の同期・親族もいる。**誰でも迷わず使えること** を、仲間内のノリより優先する。
- 式の前はエピソードを集める時期（ムービーとおもてなしAIの RAG に使う）。当日は写真の時期。
- 一番の課題は **一投稿目のハードル**。新しい機能は「最初の1件が出しやすくなるか」で判断する。

## 名前・ロゴ
- ロゴ「H&K」（明朝、& だけ金で 85%）。LINE のバーのタイトルは「UTAGE — Haru & Ken」。招待状は「WEDDING INVITATION」のまま。
- ロゴやタイトルで日付を強調しない（推測されやすい情報を画面に出さないため）。
- 新郎新婦の投稿・コメントは時刻を出さず、日付だけ（「◯分前」も出さない。当日も「11/15」）。同じ理由。管理画面は時刻を出す。

## デザインの決めごと
- **書体**：目に留めるもの（名前・数字・見出し）は明朝、読み流すもの・押すものはゴシック。MONO は黒いレース画面だけ。大きさは rem。
- **色（D案）**：枠なし・無彩色で写真が主役。地は紙の色 `#f9f8f6`。
  - テラコッタ `#b4462a` は「押して投稿する場所」だけ（＋・投稿の帯・投稿ボタン）。
  - 金はロゴの & だけ。いいねは赤。選んでいるもの（タブ・チップ）は墨の太字・墨の枠。タグは無色。
  - 色はすべて役割で説明できること。
- 白いカードを減らし、罫線と余白で区切る。絵文字は控えめ。
- 意味が違うものは形も変える（例：お題＝チップ、公開範囲＝文字とチェック）。丸いチップだらけの画面にしない。
- 小さい画面（iPhone 13 mini）で確認する。親族向けは文字を大きく。

## 文言の決めごと
- 主語を省いて自然に。「〜は？」の問いかけでそろえる。押しつけない。
- 事前に赤字のエラーを出さない。足りないときはボタンを無効にするだけ。
- 写真は「軽量版」「高画質版」と呼ぶ（低画質とは言わない）。軽量版＝当日のタイムライン・スクリーン・エンドロール。高画質版＝あとで保存して残すため。

## 投稿・エピソード
- エピソードはチェックボックスではなく、お題チップを選ぶとエピソードになる。お題を選ぶとハッシュタグが付く（既存の仕組みを維持）。
- お題（確定・7個）：笑った話／旅・おでかけ／ごはん・飲み会／意外な一面／グッときた話／水泳／秘蔵写真。プレースホルダーは「場面の例を3〜4個……問い1つ」の形。
- 一文「みんなで思い出を持ち寄ろう。ふたりとの話でも、仲間との懐かしい話でも。」
- お題チップは横スクロールにせず折り返す（2〜3行。幅 320px では3行になってよい）。
- 公開範囲の初期値は、持っているタグのうち **タグの管理の並び順でいちばん上** の1つ（全員・承認済・新郎新婦・隠したタグ・選べないタグは除く。無ければ「全員」）。新郎新婦本人も同じ。書きかけに範囲が残っていればそちら。お題を選んでも範囲は変えない。
- 公開範囲はシートに隠さず、投稿画面に「文字とチェック」でそのまま出す。下に「◯◯ に表示されます」。
- 投稿したあとも、本人は編集画面で公開範囲を変えられる（同じ「文字とチェック」）。変えるときは保存の前に確認を出す。狭めるとき「すでに見た人の画面や、保存された写真は取り消せません。範囲から外れる人のコメントも、その人からは見えなくなります。」、広げるとき「コメントも、新しく見える人に表示されます。」。コメント・エピソードの範囲もサーバーが一緒に変える。メンションの通知は送り直さない。
- 思い出は新郎新婦とのものでなくてよい。コミュニティの懐かしい話を歓迎する。
- 感情の言葉（ほっこり等）より、場面の言葉の方が書きやすい。自分の気持ちを晒すお題は避ける。

## 写真・通信
- 送るのは軽量版を先に、高画質版はボタンであとから。一覧は feed 828px・grid 400px・ぼかしの下絵。
- `wedding-media` の `/u/` は Cache-Control 1年 immutable＋Cloudflare のエッジキャッシュ。同じキーに上書きしない。
- 会場の Wi-Fi は無し。ゲスト用ルーターは持ち込まない（スクリーン用PCだけ別回線の可能性）。

## 性能の考え方
- 読み取り回数を増やさない。誰が見ても同じ集計はサーバーで短時間使い回し、自分の分だけ毎回計算する。
- 画面は前回の結果をすぐ出して裏で更新する（stale-while-revalidate）。端末のキャッシュは uid ごとに持ち、ログアウトで消す。
- Vercel の関数は東京（hnd1）。

## 運用
- 本番の Firestore Rules・インデックスは Terraform で反映する（`firebase deploy` は使わない）。Rules やインデックスを変える Issue には「オーナー作業：terraform plan / apply」を必ず書く。
- `terraform apply` は plan で中身を確認してから。関係ない差分（identity_platform_config など）があれば `-target` で絞る。
- コマンドはサブシェル `( … )` で包み、スマホからコピペできる1ブロックにする。
